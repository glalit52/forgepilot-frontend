# ForgePilot — Web app (CLAUDE.md)

Read this fully before any task. Product source of truth: `docs/PRD.md` (Final PRD v1.0, converted from the founder's .docx).

## What ForgePilot is

**A self-serve SaaS product.** It's the engineering operations layer for teams building software with AI coding agents. It is not an agency or a managed service. One workspace, three modules sharing repository intelligence:

| Module         | Purpose                                                                               | Key screens                                            |
| -------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **DevPilot**   | Coordinate AI coding agents (Claude Code, Codex): tasks, isolated sessions, logs, PRs | Command centre, tasks, sessions, workspaces            |
| **ShipSafe**   | Verify every PR (agent or human) with commit-pinned tests and evidence                | Testing dashboard, suites, runs, bugs, PR verification |
| **CodeKeeper** | Keep repositories healthy: dependencies, advisories, maintenance PRs                  | Health, dependencies, findings, maintenance            |

Customers: AI-native developers, engineering leads/CTOs, software agencies, OSS maintainers (PRD §4). Pricing: subscription plus metered usage. Plans are Free / Developer $29 / Pro $79 / Team $199 / Business $499 / Enterprise (`lib/domain/plans.ts`, PRD §18). Positioning: integrate, don't replace. It is **not** an IDE, not a model, and never auto-merges.

## The closed loop (PRD §10). Everything in the UI serves this

PLAN (task) → EXECUTE (agent in isolated workspace) → PROPOSE (PR) → VERIFY (ShipSafe) → REMEDIATE (failure → bug → fix task, capped retries) → REVIEW (human) → MERGE (in GitHub) → MAINTAIN (CodeKeeper rescans) → IMPROVE (findings → tasks).

## Product rules the UI must respect

1. **Human control by default.** Passing checks never merge. Merge happens in GitHub, and the UI says so. Sensitive actions (protected paths, secrets, migrations, network egress, budget increases) go through the approval centre.
2. **Evidence before assertion.** Every status links to its evidence: logs, traces, screenshots, diffs, advisory sources, commit SHAs.
3. **Human vs agent is always visible.** Every action shows its actor via `ActorChip`: a person, an agent (with model) or the system.
4. **Honest failure classification.** Infra/environment/flaky failures are never shown as product defects.
5. **Explainable health.** Show the component scores and weights; unknown data is shown as "Unknown", never as healthy. It is not a security certification.
6. **Transparent economics.** Show usage, quotas, projected spend, budgets and hard caps. No fake numbers: everything is computed from mock data and the app shows a "Demo data" badge.
7. **Tenant isolation and least privilege.** Every request is scoped to the active workspace. Roles are owner/admin/member/viewer (`lib/domain/permissions.ts`); hide or disable actions the role can't take, and explain why.

## How to work

- Types come from `lib/schemas`. Components never fetch: they call hooks in `lib/api/hooks.ts`.
- Every page handles loading, empty (with a next action), error (with retry) and permission-denied states.
- Use `can(role, permission)` from `lib/domain/permissions.ts` for every action button, and `PlanGate` for plan-gated features.
- Design: calm, dense, technical (Linear/Vercel/GitHub clarity). Light and dark. One violet accent for primary actions. Semantic green/amber/red. Geist font, 8px radius. Desktop-first; monitoring and approvals work on mobile.
- Accessibility: WCAG 2.2 AA, keyboard navigation, visible focus, labelled inputs, aria-labels on icon buttons, charts with text alternatives.
- Before finishing: `pnpm lint && pnpm typecheck && pnpm test` must pass; add a Playwright test per new journey.
- Explain changes in plain English in PR descriptions; the founder is non-technical.

## Decisions recorded (keep current)

- **Business model is SaaS (Final PRD).** The earlier agency/managed-service version was removed at the founder's request.
- **shadcn/ui is hand-installed** because `ui.shadcn.com` is blocked in the cloud environment.
- **The mock API is one route table** with permission per route; `docs/api-contract.md` is generated from it (`UPDATE_CONTRACT=1 pnpm test`).
- **The simulation is time-based:** each request advances sessions, runs, scans and indexing. Durations come from `FP_MOCK_RUN_MS`, `FP_MOCK_VERIFY_MS`, `FP_MOCK_SCAN_MS` and `FP_MOCK_INDEX_MS`.
- **Mock session cookies:** `fp_session` (user) and `fp_ws` (active workspace). `POST /api/mock/demo/reset` restores the seed.
- **Budgets:** agent cost is provider-reported (the customer's own API keys) plus ForgePilot-metered browser minutes; the workspace budget and hard cap govern both.
- **Advisory ids use a `DEMO-` prefix** so they can't be mistaken for real CVEs.

## Do not

- Add a real backend, database or auth provider yet.
- Add dependencies without saying why in the PR.
- Use third-party logos (use `Monogram`), real company names, real CVE ids or secrets.
